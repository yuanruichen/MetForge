# Completed-stage handoff

A checkpoint is a coherent set of saved, validated results addressing an agreed
question/acceptance criterion. It is not each computation, intermediate figure
or failed method gate. `metforge-analysis` invokes `metforge-ppt` at this checkpoint
through the host agent; this does not create a background job or promise future
unattended work. Respect an opt-out, pause or narrower output request.

Recover the following from existing reports and manifests. A new elaborate file
format is unnecessary when the project's records already contain the information:

- Project/stage, question, acceptance criteria and status.
- Exact requirements, method/run records and code revision.
- Model/experiment/ensemble, period/season, domain/grid/calendar, variables/units.
- Definitions, thresholds, reference, preprocessing, sampling and weighting.
- Final figure/table paths, versions and hashes; exclude superseded versions.
- Numerical findings with source rows/panels and permitted interpretation.
- Null/opposing results, sensitivity, missing samples and censoring categories.
- Uncertainty, causal limits, work not run and the next test.

Create a slide-to-evidence manifest. Notes retain detailed settings and method
citations; visible slides stay concise. Copy numerical claims from saved results.
Additional diagnostics require separate analysis scope and the published-method
gate. A completed early stage does not complete a later mechanism phase; monthly
maps do not validate daily processes. Budget terms, composites, covariances and
model contrasts do not by themselves establish causal origin or propagation.

An incomplete/method-blocked stage does not trigger a completed-results deck.
An explicitly requested progress presentation may show verified work and blockers
while retaining the incomplete status and marking what was not run.
